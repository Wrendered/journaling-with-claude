# Weekly Review

Read [the shared memory contract](../../../docs/memory-contract.md) before the first capture, state update, or import in a session. Use AGENTS.md for privacy, attribution, and current-context precedence.

1. Capture the request. Read current context and the generated timeline, then open the week’s source records. Use the user’s timezone; avoid treating late-night recording time as an event date.
2. Offer a compact review of what happened and what remains open. Distinguish user reports from your interpretation. Count independent occurrences, not duplicated summaries.
3. Write an attributed, source-linked synthesis to private/reviews/YYYY-Www.md. This is an editable wiki page, not a raw source. Preserve earlier revisions through backup; never rewrite legacy weekly journals.
4. Update dashboard and relevant wiki pages to reflect explicit choices. Add sourced state assertions for actual changes. Permanent self-map claims require supported passages and user adoption.
5. Rebuild views and run audit. Use the backup skill for a verified snapshot. Report any actual failure without claiming success.
6. Do not commit private files or change Git remotes. A review or backup request does not authorize a commit.
